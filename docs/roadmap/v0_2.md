# v0.2

## Anchor regex magic with range offsets

> Tracked in
> [bettongia/mediatype_detector#1](https://github.com/bettongia/mediatype_detector/issues/1).

`RegExpMatch.matches` resolves range offsets with an unanchored
`hasMatch(content.substring(pos))`, so a pattern may match past the declared
range end and the loop over candidate positions is redundant. The single-offset
branch anchors correctly via `matchAsPrefix`.

Switching the range branch to `matchAsPrefix(content, pos)` enforces the range
bound. This is stricter than current behaviour, so some types that match today
will stop matching — a behavioural change to detection output, which is why it
belongs in a minor release rather than a patch.

Scope:

- Anchor the range branch in `lib/src/mimeinfo/magic.dart`.
- Re-check the pinned expectations in `test/tika_test.dart` (`docbook_4.xml`,
  `test.atom`) and drop their explanatory comments where they no longer apply.
- Update the Regex paragraph in `docs/spec/README.md`, which currently documents
  the `hasMatch` behaviour as intended.
- Sweep for other Tika regex-with-range types whose result may change.

Not user-visible via the blended `detect()` today — Freedesktop's rootXML
matching compensates for both known samples. The risk is Tika-only types that
Freedesktop does not cover.
